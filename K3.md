This is an inference-only FP32 adapter for the two-layer `surface_min`, stride2,
normalizing initializer and scale-factor1 composer used by the default predictor.
It requires eval mode throughout and rejects autocast. It accepts small even grids
for source-contract tests; the full model still requires its normal1536² input.

### Exact capture and replay

`SharpAdapter.capture(image, disparity_factor, ...)` runs the **original
`RGBGaussianPredictor.forward`**. Temporary forward hooks snapshot its actual:

- `MonodepthOutput`, including the original encoder and decoder features;
- metric depth returned by `depth_alignment(..., depth=None)`;
- `InitializerOutput`, including base Gaussians, feature input and global scale;
- `prediction_head` deltas;
- final normalized-camera-frame Gaussians.

The hooks are removed in `finally`, including on inference failure. Capture also
stores a detached input snapshot, camera disparity factor, the exact normalized
depth and depth factor returned by upstream `_rescale_depth`, metadata and optional
camera/provenance records. Aliases between encoder/output feature lists are retained.

`replay(capture)` runs the **same upstream forward** on a shallow predictor copy
whose monodepth module simply returns the captured `MonodepthOutput`. Thus it
executes the original disparity conversion, identity inference alignment,
initializer, Gaussian decoder/head and composer, without executing the expensive
monodepth network. The caller's modules and module registry are untouched.

### Fixed normalization: source operations, not approximate formulas

The report's shorthand `Z / global_scale` is **not** used to reconstruct baseline
normalized depths. Floating-point reciprocal round trips need not be bit-exact.
The adapter retains upstream `_rescale_depth(Z_original)`'s normalized depth and
its original `depth_factor` directly.

For accepted corrected depths, it uses `Z_candidate * original_depth_factor` and
rejects values outside normalized support `[1,100]`. It then calls a shallow copy
of the **actual `MultiLayerInitializer`**, with `normalize_depth=False`, on those
already normalized depths. This invokes upstream's exact pooling, `_create_base_scale`,
base-coordinate/color preparation and `prepare_feature_input` implementation.
No alternate pooling, scale formula or activation implementation is used.

From this candidate initializer output, only the following are selected:

- accepted visible pixels in `feature_input[:,3:4]`;
- owned visible cells in `mean_inverse_z_ndc[:,:,0]` and `scales[:,:,0]`.

All other base fields, secondary depth/features, and the original `global_scale`
are retained. Rejected pixels are copied directly from baseline tensors; they are
not recomputed through reciprocals. An identical inverse-depth input is recognized
before reciprocal conversion, including the baseline's epsilon-offset minimum.

### Decoder and composer preservation

`replay_corrected(...)` calls the original Gaussian decoder/head with the corrected
feature input and captured original encodings. It selects the new14-channel deltas
only in owned visible cells. Every secondary delta and every unowned visible delta
is copied exactly from the capture. The unchanged upstream composer consumes these
selected inputs and the original global scale.

`frozen_delta=True` is a supported numerical ablation: all baseline deltas remain
unchanged, while owned visible base depths/scales can change. It skips the Gaussian
decoder pass. No-op/fully rejected corrections also skip that pass, but still run
the real composer rather than simply returning the saved Gaussians.

## API and caller obligations

The main API accepts an existing, fully loaded predictor:

```python
from experiments.sharp_hybrid_research.sharp_adapter import (
    SharpAdapter, save_capture, load_capture, export_ply,
)

adapter = SharpAdapter(predictor.eval())
capture = adapter.capture_rgb(rgb_uint8, f_px, device="cpu",
                              provenance={"input_file": "/mnt/c/depth_issue/bridge.png"})
replayed = adapter.replay(capture)

# Already registered SHARP-grid tensors supplied by a later stage:
result = adapter.replay_corrected(
    capture,
    inverse_depth=q_metric,   # FP32 [B,1,H,W], units 1/metre
    accept=accept_mask,        # bool [B,1,H,W]
    surface_ids=labels,        # int64 [B,1,H,W], -1 unknown, >=0 surface IDs
    cell_allow=cell_mask,      # optional bool [B,1,H/2,W/2], caller veto
)
```

`predictor`, RGB/focal and correction tensors above are caller inputs, not objects
created by this module. Tensor-level `capture(image,k,camera=...)` is also available;
`k` must be same-device FP32 `[B]`, and image is `[B,3,H,W]` in `[0,1]`.
`capture_rgb` handles a single native RGB image using the pinned CLI's exact square
resize and camera operations. It records original size/focal, resized intrinsics,
identity extrinsics, `align_corners=True` and `square_stretch`. It does not estimate
a focal length. Tensor-only captures may have `camera=None`; export requires a real
camera record supplied by the caller or `capture_rgb`.

All correction tensors must already be on the same device/grid as the capture.
This implementation does not infer labels, rasterize native-resolution masks, align
relative predictions, or estimate confidence. In particular, `accept` and surface
IDs assert that the caller has already validated geometric ownership. IDs are local
identities, not semantic classes: assign different IDs to distinct wires/surfaces.

### Conservative cell ownership policy

1. Exclude unselected, nonfinite, nonpositive, unknown-label and out-of-support
   pixels. Nonfinite inverse depths are never reciprocated; overflowed positive
   reciprocals are rejected before entering the initializer.
2. Recognize exact identity inputs as no-ops.
3. Evaluate proposed pooling using upstream initialization. Track old and proposed
   max-disparity winner indices in full-image row-major pixel coordinates.
4. Reject a cell if its **changed, valid corrections** carry multiple surface IDs.
5. Require a changed pooled depth. A deeper correction to a losing sample cannot
   take ownership of the Gaussian cell or modify its decoder input. Lowering an old
   foreground winner may legitimately reveal an unchanged background sample; this
   withdrawal is allowed and its new pooling winner is recorded.
6. Apply the optional cell veto. Revert **all** rejected cell corrections before
   forming the final corrected features/metric-depth record.

A same-surface pair within a cell can be accepted; distinct corrected surfaces
within that cell are conservatively rejected. A structure spanning two cells can
own both. Unknown subpixel collisions cannot be resolved from depth/masks alone:
callers must veto them or withhold acceptance. This is ownership bookkeeping, not
a proof of correct monocular geometry or a Gaussian densification mechanism.

`InitializerEdit.diagnostics` exposes invalid/support/unknown masks, candidate and
touched masks, collision/pool-unchanged masks, old/proposed/applied winner indices,
and visible-vs-secondary order reversals. Layer ordering is recorded, never sorted.

### Returned records

- `SharpCapture`: baseline tensors and metadata.
- `InitializerEdit`: selected initializer, hybrid metric and normalized depth,
  accepted-pixel/owned-cell masks and diagnostics.
- `HybridReplay`: initializer edit, selected deltas, final `Gaussians3D`.

NamedTuple field names/types remain upstream types. Captures are frozen dataclasses,
but their tensors are not write-protected: treat them as immutable. The adapter
never edits the caller's capture or original modules in place.

## Cache provenance and export

`save_capture(capture, path)` stores a schema-versioned tensor/dictionary payload;
`load_capture(path, device=...)` uses `torch.load(..., weights_only=True)`. The parent
directory must exist, and saves refuse overwrite. CPU transfer preserves feature
aliases so GPU feature lists are not separately transferred for each reference.

The record contains source hashes/revision, a SHA256 over actual state-dictionary
tensor contents, explicit initializer/composer/monodepth/decoder configuration,
prepared-image hash, units, layer order, dtype, shapes, torch version and optional
caller provenance. Replaying with different source, weights or configuration fails.
State hashing is a one-time adapter-construction cost, potentially substantial for
the released model. Standard in-place weight changes/moves are detected thereafter;
arbitrary `.data` mutation is unsupported. Recreate the adapter after moving or
loading the predictor, and load captures onto its device.

For full-input replay:

```python
save_capture(capture, "/mnt/c/depth_issue/results/sharp_hybrid/baseline_cache/capture.pt")
restored = load_capture(
    "/mnt/c/depth_issue/results/sharp_hybrid/baseline_cache/capture.pt", device="cpu")
replayed = adapter.replay(restored)
export_ply(replayed, restored.camera,
           "/mnt/c/depth_issue/results/sharp_hybrid/baseline_cache/replayed.ply")
```

These destination paths are the planned K3 baseline-cache directory; no full-model
cache or PLY was generated in this implementation session. `export_ply` calls the
original `unproject_gaussians` and `save_ply`. It requires batch1 to avoid merging
multiple scenes into one PLY and refuses overwrite. World conversion uses upstream
covariance transforms/CPU float64 SVD and the original export colorspace conventions.
